# 비주얼 리부트 설계 (데모 0.0.1 → 벡터/카툰 아트)

## 배경 (Why)

`game-unity`는 웹 프로토타입("이순신 서바이버")을 Unity로 포팅한 데모 0.0.1이다. 로직/시스템은 완성되어 있으나(16개 태스크 완료, 55 EditMode + 1 PlayMode 테스트 통과), 아트가 4프레임짜리 저해상도 픽셀아트 placeholder이고 프레임 간 차이가 거의 없어 정적으로 보인다. 배경도 없이 카메라 단색(`#0D0D12`)만 깔려 있다.

사용자는 이 데모를 다음 단계로 업그레이드하고 싶어하며, 우선순위는 (1) 비주얼/연출 강화 → (2) 콘텐츠 확장 → (3) 게임 시스템 개선 순으로 정했다. 이 스펙은 그중 **비주얼/연출 강화**, 그 안에서도 **스프라이트/애니메이션 품질**과 **배경/화면 연출** 두 가지를 다룬다.

## 범위 (Scope)

**포함:**
- 플레이어, 적 2종(basic/fast), 보스, 화살 투사체(arrow), 메달 픽업(medal) 스프라이트를 벡터/카툰(flat-shaded) 스타일로 전면 교체
- 정적 배경 이미지 1장 추가 (parallax 없음)
- 걷기 애니메이션 프레임 수 확장 (4 → 6~8프레임), 기존 프레임 스왑 방식(`SpriteFlipbook.cs`) 유지
- 새 아트에 맞춘 스프라이트 임포트 설정 조정 (필터모드, pixelsPerUnit)

**제외 (Out of scope, 별도 스펙으로 분리):**
- UI/HUD 재디자인 (체력바, 경험치, 레벨업 카드 등) — 사용자가 강화 포인트로 선택하지 않음
- 파츠 기반(뼈대/트윈) 애니메이션으로의 전환 — 리깅 작업이 커서 별도 스펙 필요
- 배경 parallax, 다중 레이어, 타일링 — 이번엔 정적 배경 1장만
- 콘텐츠 확장(신규 무기/적/보스), 게임 시스템 개선(밸런스, 진행 구조) — 다음 순번 스펙

## 에셋 파이프라인

1. Hugging Face 이미지 생성 도구(`gr1_z_image_turbo_generate` 등)로 각 캐릭터/오브젝트를 벡터/카툰 스타일로 생성
2. 배경 제거 및 정리 후 투명 배경 PNG로 후처리
3. 기존 스프라이트시트와 동일한 파일명·해상도 규격으로 정렬해 `Assets/Sprites/`의 기존 파일을 교체 (씬/프리팹의 참조 경로가 그대로 유지되도록 하여 재연결 작업 불필요)

> [!WARNING] OPEN ITEM: 이미지 생성 도구가 프레임 간 일관성(같은 캐릭터가 여러 프레임에서 동일하게 보이는지)을 얼마나 잘 유지하는지는 실제 생성 전까지 검증되지 않음. 프레임 간 불일치가 심하면 후보정 작업이 추가로 필요할 수 있음.

## 애니메이션 방식

기존 `SpriteFlipbook.cs`가 스프라이트시트의 프레임을 일정 간격으로 전환하는 방식을 그대로 사용한다. 벡터 스타일에서도 프레임 스왑 자체는 기술적으로 동일하게 동작하므로 시스템 변경은 없다. 다만 정적으로 보이지 않도록 프레임 수를 4 → 6~8장으로 늘린다.

파츠 분리(팔다리를 낱장으로 분리해 회전/트윈) 방식은 더 자연스러운 애니메이션을 만들 수 있지만 리깅과 애니메이션 시스템 교체가 필요해 리스크가 크므로 이번 스펙에서는 다루지 않는다.

## 엔진 설정 변경

- 스프라이트 임포트 필터모드: `Point (no filter)` → `Bilinear`로 전환 — 벡터 아트는 안티에일리어싱이 있어야 자연스럽게 보임
- `spritePixelsToUnits` 값을 새 아트 해상도에 맞춰 재조정
- 배경: 카메라 단색 배경(`m_BackGroundColor`) 대신 배경 스프라이트 오브젝트 1개를 씬에 추가 (Sorting Order로 최하단 배치)

## 테스트 / 검증

- 기존 55 EditMode + 1 PlayMode 테스트는 게임 로직만 검증하므로 아트 교체로 깨지지 않을 것으로 예상됨. 교체 후 `run-tests.bat`, `run-playtest.bat`로 전체 재실행해 회귀 확인
- 육안 확인: 에디터에서 Play 모드로 각 캐릭터/이펙트가 의도대로 보이는지, 배경과 겹치거나 가려지는 요소가 없는지 확인

## 리스크

- AI 생성 아트가 여러 프레임에서 캐릭터 일관성을 유지하지 못할 위험 (위 OPEN ITEM 참고)
- 새 아트 해상도가 기존 콜라이더/스케일과 안 맞을 경우 캐릭터 크기·충돌 판정이 어긋날 수 있음 — 교체 후 실제 플레이로 확인 필요
